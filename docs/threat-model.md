# 威胁模型与安全设计

open·kritt 在**可能不可信的源代码**上运行 AI 智能体，并处理**模型/提供商凭据**和仓库令牌。本文档描述信任边界、数据流向，以及如何安全部署。它是对 [SECURITY.md](../SECURITY.md) 中披露流程的补充。

> **一句话总结：** 扫描智能体以 root 身份在一次性容器中运行，工作区可写，且可直接访问互联网。将仓库和模型输出视为不可信，隔离 Docker 主机，最小化凭据权限，并保持 API 私有。

## 组件与数据流

| 组件 | 角色 | 信任级别 |
| --- | --- | --- |
| `frontend` | UI（React/Vite） | 面向操作员 |
| `backend` | REST API + Postgres 访问（Express/Prisma） | 面向操作员，**默认无认证** |
| `database` | Postgres — 工作流、扫描、发现结果 | 可信存储 |
| `engine` | 领取扫描任务、检出仓库、运行执行框架 | **分析不可信代码与提示词** |
| `executor-view` | 执行器状态/账户的只读视图 | 面向操作员 |

流程：UI → backend（创建工作流/扫描）→ Postgres 队列 → **engine** 检出目标仓库（+ 依赖仓库），构建工作区，并通过 AI **执行框架**（`codex` / `claude-code` / `grok-build`）运行每个工作流步骤，该框架将仓库内容发送到**已配置的模型/提供商端点** → 结果写回 Postgres → UI。

工作流和脚本后生成使用单独的 Postgres 队列。自然语言请求会发送到所选提供商，但生成执行框架在运行时没有模型工具或仓库访问权限。Postgres 保留请求，仅存储经过验证的草稿或安全的失败详情，不存储无效的原始模型输出；后端在 UI 可以审查之前会再次验证已完成的草稿。

## 信任边界

1. **操作员 ↔ backend/UI。** API 和 UI 默认无认证。任何能访问它们的人都可以读取/创建扫描、读取发现结果，并更改提供商账户配置。**你必须自行强制的边界**（网络隔离 / 带认证的反向代理）。
2. **Engine ↔ 被分析的代码。** 引擎检出任意仓库并对其运行 AI 智能体。启用工具的任务以 root 身份在一次性嵌套容器内运行，每个任务有可写的检出目录，并可直接访问外网。任务仅接收其检出目录、任务主目录和所选提供商凭据；它不会接收 Docker socket 或引擎的其他密钥挂载。引擎本身确实会接收宿主 Docker socket 以便创建这些运行器，必须被视为特权组件。
3. **open·kritt ↔ 模型/提供商。** 仓库内容会发送到已配置的 OpenAI/Codex、Anthropic、OpenRouter 或 xAI 端点。这是一个数据出口边界。
4. **主机 ↔ 密钥。** 提供商 API 密钥和 `GITHUB_TOKEN` 存放在 `.env` 中。后端可以从 Accounts 更新该文件，引擎仅将所选提供商凭据传入每个执行框架任务。

## 需要保护的资产

- **提供商凭据**（`OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`OPENROUTER_API_KEY`、`XAI_API_KEY`、`CODEX_API_KEY`）以及 Codex/Claude 登录主目录。
- 用于检出私有仓库的 **`GITHUB_TOKEN`**。
- 被扫描仓库的**源代码**（通常敏感/专有）。
- **发现结果**（真实漏洞 — 在修复/披露前属于敏感信息）。
- **生成请求**，可能描述私密的安全研究目标，并保留在生成队列中。

## 主要威胁与缓解措施

### 1. 不可信代码与提示词注入
引擎分析受攻击者影响的代码，仓库可能包含精心构造的内容，用于操纵智能体（提示词注入）以窃取密钥或行为异常。

自然语言工作流和脚本后生成请求同样是不可信输入。

- **设计缓解措施：** 每个启用工具的任务都会获得一次性容器、可写的每任务检出目录、复制的任务主目录和专用 Docker 网络。任务不挂载 Docker socket、数据库、项目 `.env` 或其他任务。执行框架输出为受 Schema 约束的 JSON。草稿生成调用运行时禁用模型工具、用户规则/设置和会话持久化；引擎和后端验证器在草稿到达编辑器或资源表之前拒绝格式错误的草稿。
- **有意赋予的能力：** 扫描智能体在其任务容器中以 root 身份运行，可使用 Bash、安装包、编译或测试目标，并直接访问互联网。任务容器不是针对内核或容器运行时漏洞的安全边界。
- **操作员缓解措施：** 在**专用 VM 或 Docker 主机**上运行完整技术栈。不要将其与无关的敏感工作负载共置。假设任何扫描都可能是恶意的。

### 2. 密钥窃取
被入侵/注入的智能体可能尝试读取凭据或将数据外发。

- 将密钥存放在 `.env` 和提供商登录/凭据存储中（**均已 gitignore**）；`gitleaks` pre-commit Hook 可防止提交它们。仅向引擎提供其所需的令牌。
- 优先使用**范围狭窄、短期有效**的 `GITHUB_TOKEN`（只读，仅限你扫描的仓库）。定期轮换提供商密钥。
- 扫描运行器**默认可直接访问外网**，以便智能体进行研究、安装工具和获取依赖。如果你的部署需要允许列表或无互联网，请在 open·kritt 之外的 Docker 主机、防火墙或网络策略层强制执行。
- `ENGINE_CODEX_AUTO_UPDATE` 默认为 `false`。启用它会额外信任并需要访问 npm 镜像仓库。

### 3. 数据出口到模型提供商
扫描默认会将代码发送到外部端点。

- 在扫描敏感代码之前，了解**你的数据去向**。支持的设置路径使用 Codex/OpenAI、Anthropic、OpenRouter 或 xAI（Grok Build）凭据。
- 查看你所使用端点的提供商数据保留条款。

### 4. 无认证的 API 暴露
`/api/*` 默认**无认证**。

- 不要将其绑定到公共接口。在前面放置你自己的认证/授权代理，或仅将其保留在可信网络上。
- 任何能调用 API 的人都可以排队扫描或 AI 草稿生成任务，并消耗提供商配额。在代理处应用认证、网络控制和速率限制。

### 5. 供应链（open·kritt 自身）
- 依赖由 **Dependabot** 更新，并通过 PR 上的 **Dependency Review** 审查；**CodeQL** 扫描代码。Docker 基础镜像**固定版本**（绝不使用 `:latest`）。
- 引擎可在启动时以及当 `ENGINE_CODEX_AUTO_UPDATE=true` 时每天检查 npm `@latest` Codex 包。默认禁用；启用它即有意为该可执行文件信任 npm 镜像仓库。
- 计划中：SBOM 生成和签名发布产物（见路线图）。

## 安全部署检查清单

- [ ] 在**专用 VM 或 Docker 主机**上运行完整技术栈。引擎控制 Docker 守护进程，扫描运行器以 root 身份运行并可直接访问外网。
- [ ] 如果直接互联网访问不符合你的策略，添加主机级出口控制。
- [ ] 在 backend API 和 UI **前面放置认证**。
- [ ] 使用**最小化、短期有效的 `GITHUB_TOKEN`**；轮换提供商密钥。
- [ ] 选择**数据处理**与代码敏感度相匹配的模型端点。
- [ ] 保持 `.env` 和 `.data/` 凭据存储私有；绝不提交它们。

## 范围之外

- 需要主机或操作员账户已被入侵的攻击。
- 本文档明确警告的配置错误（例如将无认证的 API 暴露到互联网）。
- 第三方模型提供商自身的安全性。

**open·kritt 自身代码中**的漏洞始终在范围内 — 请通过 [SECURITY.md](../SECURITY.md) 报告。
