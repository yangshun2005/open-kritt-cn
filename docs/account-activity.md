# 活跃的提供商账户

使用 **Accounts → Active** 选择哪些已保存的账户可以接收新分配。现有账户和新增账户默认处于活跃状态。关闭开关会保留凭据和配置；再次打开即可复用该账户。认证和配额状态仍与保存的开关分开显示。

该设置适用于已注册提供商的已保存登录信息和 API 密钥，包括环境密钥。拥有多个账户的提供商使用其活跃子集。如果没有可用的活跃凭据，请在 Accounts 中激活一个账户后重试。启动模型使用的手动操作也需要活跃账户。登录、凭据替换、状态刷新和配额管理对非活跃账户仍然可用。

引擎在账户选择期间以及调用获取其分配槽位时再次检查资格，包括等待容量之后和重试之前。在开关保存之前已获准的调用可以完成。先前选中但在获准前变为非活跃的账户会以可操作的错误消息失败；绝不会被静默复用。

偏好设置存储在 `account-activity.json` 中，位于 `OPEN_KRITT_PROVIDER_CREDENTIALS_PATH` 指定的提供商凭据存储旁边。后端以原子方式写入此文件，引擎在每个分配边界读取它。现有的共享凭据目录为两个服务提供同一文件；无需数据库迁移或新增挂载。缺失的偏好设置默认为活跃以保持兼容，而不可读或无效的偏好设置会阻止分配，直到修复为止。请将此文件与凭据存储一起备份。偏好设置与提供商及其配置的凭据位置关联，因此在那里重新连接或替换凭据会保留已保存的设置。

该文件只有一个写入者：应用程序的后端。请一起部署后端和引擎的更改，以便两个服务都遵循该设置。

账户 API 响应使用 `active` 表示已保存的偏好设置，使用 `available` 表示先前以 `active` 暴露的凭据健康布尔值。请更新将 `active` 用作认证健康检查的客户端。使用 `PATCH /api/accounts/:provider/account/:activityId/active` 并在 JSON 正文中传入布尔值 `active` 来切换已观察到的账户。现有的登录和移除账户 ID 保持不变。
